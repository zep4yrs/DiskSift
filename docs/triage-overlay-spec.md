# AI 分诊图层（Triage Overlay）· 功能规格

> 状态：构想完善稿（2026-09-27）。原始想法来自用户：**"占用大的、可清理的、建议迁移的按不同颜色标，并在文件夹目录同步"**。本文将其完善为可实施的交互设计。
> 目标版本：26.1.2.0「自动化 + 脚本生态」第四柱（替代原"AI 起草脚本"独立项，后者成为本功能的下游动作）。
> 隐私红线不变：AI 分类只看**元数据**（路径/大小/文件数/扩展名分布/抽样路径名），绝不读文件内容。

## 1. 一句话

给空间图（Treemap）和资源管理器（树视图）加一层 **AI 分诊染色**：AI 按你的规则给每个大目录下判定——可清理 / 占用大需决策 / 建议迁移 / 系统不可动 / 不确定——整个磁盘地图一眼看出哪里能下手。

## 2. 交互流程

### 2.0 空间图点击语义（选中与下钻分离——解决"点块看详情"与"点开子目录"的冲突）

| 操作 | 行为 |
|---|---|
| **单击块** | 选中 → 详情卡（地图角落浮动，不遮挡：AI 判定 + 理由 + 动作按钮 + **「进入目录」按钮**） |
| **双击块** | 直接下钻进该目录（高频操作给快捷路径） |
| **右键块** | 现有菜单（复制路径 / 资源管理器打开 / 右键删除）原样 |
| **面包屑** | 返回任意上级（已有） |

同一套语义无 overlay 时也成立（单击选中看信息、双击下钻）——交互模型全时段一致。
下钻后 overlay 不丢：判定缓存按路径存，子目录用自己的分类色重排；面包屑返回即恢复上级染色。

### 2.1 深层可清理目录的发现（treemap 只画 2 层的盲区解法）

问题：可清理目录常在 4-5 层深（如 `AppData/Local/pip/cache`），当前图上看不到它的色块。

三层解法（叠加使用）：

1. **祖先聚合徽标**：任何祖先块的角落挂 mini-pill「🟢 12.4 GB」（= 其子树内可清理字节的聚合），
   数据从判定缓存沿树向上聚合（渲染期计算，零额外请求）。看到徽标 = 下面有货；
   单击块 → 详情卡「内含可清理子目录」小节列出直达清单（每条点击 = 自动展开祖先链 + 下钻定位）。
2. **「只看可清理」聚焦模式**：工具行开关。开启后非可清理块淡至 12% 透明度，
   可清理块保持高亮且**祖先链自动展开**（地图按需重根到最近公共祖先，每条可清理项旁标注完整面包屑）——
   10 个深层缓存目录一眼全可见，类似 WizTree 的过滤模式。
3. **既有兜底不变**：巡查/分诊（TriageView）本来就是全深度平铺列表（不受 2 层渲染限制），
   深层可清理目录在那里永远有一席；树视图按同步色条滚动也能找到。


```
扫描完成（已有）
   ↓  自动触发（可在设置关）
AI 批量分诊：按体积降序逐个分析 > 阈值 的目录
   ↓  结果渐进上色（大目录先亮，用户无需等全量）
空间图色块染色 + 树视图行加色条
   ↓  单击色块
详情卡（角落浮动，不挡图）：AI 判定 + 理由 + 「进入目录」+ 三个动作按钮
   [清理] → 跳对应清理路径   [迁移] → BlueTidy 建议   [忽略] → 反馈入库
```

- **渐进上色**：AI 按体积从大到小出判定，图先从最大的块开始变色——用户几秒内看到价值，不等全量完成
- **规则先行，AI 兜底**：有 scaffold 命中的目录直接用规则判定（零成本、即时）；只有"未识别"目录才走 AI。AI 挂了/没配 key → 仍有规则染色层，功能不瘫
- **缓存**：判定按 `路径 + 大小 + 文件数` 签名缓存（localStorage 或 secure 存储），目录没变不重问 AI

## 3. 分类体系（五判定 + 一动作）

复用 TriageView 既有的桶语义与语义色（全站一致）：

| 判定 | 颜色（色块叠加） | 来源 | 点击后动作 |
|---|---|---|---|
| 🟢 可清理 | 绿（safe 桶色） | scaffold 命中 safe 桶 / AI 判缓存类 | 跳清理 tab 或一键回收（两步确认） |
| 🔵 占用大需决策 | 蓝 | 体积大但非缓存（常装软件/常用目录） | 展开看子项 / 问 AI 追问 |
| 🟣 建议迁移 | 紫 | C 盘上的"装机型"目录特征（volume 信息 + 注册表线索） | **提示用 BlueTidy 搬**（姐妹产品导流；v1 先只给建议文案） |
| ⚫ 系统不可动 | 灰 | 系统路径规则（已有 NEVER_TOUCH 清单） | 无动作，仅标识 |
| ❓ AI 不确定 | 白 + 虚线边 | AI needs_inspection=true | "让 AI 看更深"（抽样子路径再判） |

**色块染色方式**：不替换 treemap 的尺寸语义——在既有色块上加**左缘 4px 判定色条**或 12% 透明度叠加（暗色模式同样适配），图例条常驻在 tab 工具行。

## 4. 联动（双向，复用 v26.1.1.0 的同步基建）

- 空间图色块判定 → 树视图对应行**左缘同色条 + 同款图标**（sync-nav 已有 focusPath/scrollIntoView 机制，加一个 classification 查询即可）
- 树视图行拖给 AI → 判定结果同样写回缓存 → 两处同时变色
- TriageView 分桶与本图层共用同一份判定缓存（一个目录的判定三处一致，不会出现树说可清、图说存疑）

## 5. 行动闭环（"更完善的操作"部分）

1. **可清理但无脚本覆盖**的目录 → 详情卡多一个按钮：**"让 AI 起草脚本"**（原独立 ideas 落到这里）——AI 按 14-phase 裁剪版起草用户级 scaffold，**自动跑红线检查**，过线才允许保存到用户脚本目录；不过线直接拒绝并说明原因
2. **建议迁移**的目录 → 详情卡说明 + （v2）深度链接 BlueTidy
3. **用户反馈闭环**：「忽略此判定」存入反馈表，下次同类目录的 AI prompt 带上"用户曾判定 X"——越用越准
4. 全部判定与反馈只存本机

## 6. 边界与成本控制

- 只分析 **> 阈值**（默认巡查阈值 1GB，可调）的目录；小目录永不上 AI
- 批量速率限制：AI 请求串行 + 可随时停止；成本预估在启动前展示（"约 N 次请求"）
- 未配置 AI → 图层退化为纯规则染色（scaffold + 系统规则），功能不消失
- 隐私不变：请求载荷与现有 advisor 完全一致（元数据 + ≤20 条抽样路径名）

## 7. 已决（2026-09-27 用户拍板）

1. **判定缓存 → 文件**：`%APPDATA%` 存储目录下 `triage-cache.json`（与 secure.json 同目录、同原子写模式）。理由：判定条目可达数千，localStorage 5-10MB 上限且同步 IO；文件可随数据目录迁移。
2. **触发 → 两层**：规则层**自动**（扫完即染色，零成本开箱即用）；AI 层**半自动**——扫完显示一次性提示条「AI 可分诊 23 个未知目录 · 约 23 次请求」+ [开始] 按钮（用户点才花钱）。
3. **迁移 v1 = 纯文案**（「此类目录适合用搬家工具迁移」）；BlueTidy 深链进 v2。
4. **免费 AI 接入引导（用户追加）**：AI 层的提示条对未配置用户变成**接入引导**——提供免费方案一键路径：本地 Ollama（零成本离线）/ GLM-4-Flash（官方免费档）/ 硅基流动免费模型等，点开直达设置页并预填 Base URL/Model。若用户指的是某个特定免费服务，提供名字即可加入引导清单。
